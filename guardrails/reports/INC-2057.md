## Root cause
`shopfront/billing.py:15` and `billing.py:26` — two cooperating bugs.  
1. `round(subtotal * (1 + item.tax_rate), 2)` uses Python's built-in `round()` which applies banker's rounding (round-half-to-even); finance policy requires round-half-up. A $1.005 item rounds to $1.00 instead of $1.01.  
2. `int(invoice_total(items) * 100)` accumulates per-line floats, then truncates. Float imprecision means a true $69.57 sum can be represented as 69.56999…, truncating to 6956 cents instead of 6957.

## Bug class
Monetary arithmetic performed with binary floating-point (`float`), producing banker's rounding and accumulation truncation errors at the cent level.

## Fix
Two minimal changes to `shopfront/billing.py`:
1. Added `from decimal import Decimal, ROUND_HALF_UP` and `_CENT = Decimal("0.01")`.
2. `line_total()`: converts `unit_price` and `tax_rate` to `Decimal(str(...))` before arithmetic, rounds with `ROUND_HALF_UP` — eliminates banker's rounding.
3. `invoice_total_cents()`: sums raw Decimal values across all line items with a single `quantize(ROUND_HALF_UP)` before `int()` conversion — eliminates float truncation.

The dataclass field annotations remain `float` for public API compatibility; conversion happens internally, which is the smallest correct change.

## Guardrail

Fires on the original `shopfront/billing.py:8` (`unit_price: float`).
